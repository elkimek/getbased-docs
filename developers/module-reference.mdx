# Module Reference

Modules live under `js/`. The app has hundreds of focused TypeScript modules, compiled to JavaScript by TypeScript 7. This page is a guided implementation map, not a promise that every small hook, delegate, or helper file has its own long section. It is grouped by ownership area. Follow the app architecture contract for dependency direction; `.ts` filenames identify authored source, while imports and browser URLs retain `.js` runtime specifiers.

---

## Layer 1 — Foundation

### `schema.ts` and `marker-schema/`

`schema.ts` is the stable compatibility facade for the modular biomarker catalog, range registries, unit conversions, pricing, and environment thresholds. Category definitions and immutable marker identities are authored in category modules under `marker-schema/`, composed by `marker-schema/index.ts`, and generated into `marker-schema.ts`; contributors must not edit the generated file directly.

**Key exports:**
- `MARKER_SCHEMA` — 197 core entries across 19 categories, including the 22-entry `calculatedRatios` category
- `UNIT_CONVERSIONS` — keyed by `"category.markerKey"`: `{ type: 'multiply', factor, unit }` for canonical→US compatibility; schema-wide profile resolution lives in `unit-profiles.ts`
- `OPTIMAL_RANGES` — keyed by `"category.markerKey"`: `{ optimalMin, optimalMax, optimalMin_f?, optimalMax_f? }`
- `PHASE_RANGES` — keyed by `"category.markerKey"`: `{ menstrual: { min, max }, follicular: {...}, ovulatory: {...}, luteal: {...} }` — covers `hormones.estradiol`, `hormones.progesterone`, `hormones.lh`, and `hormones.fsh`
- `CONTEXT_REFERENCE_RANGES` / `CONTEXT_OPTIMAL_RANGES` — age-, sex-, and date-resolved guidance consumed by the active-data pipeline
- `SPECIALTY_MARKER_DEFS` — re-exported from `adapters.ts` as `ADAPTER_MARKERS`. Used by `migrateProfileData()` and `buildMarkerReference()`
- `BUILTIN_MARKER_IDENTITIES`, `BUILTIN_MARKER_DOT_KEY_ALIASES`, `getBuiltinMarkerId()`, `getBuiltinMarkerDotKey()`, and `resolveBuiltinMarkerDotKey()` — immutable `gb:marker:*` IDs plus current and legacy location compatibility exports
- `CHIP_COLORS` — status → CSS color string
- `MODEL_PRICING` — AI model pricing metadata, keyed by provider/model

**Window exports:** none

### `marker-schema/index.ts` and `marker-schema.ts`

`marker-schema/index.ts` is the authoring composition root. It imports the category source modules in stable order and exports the catalog inputs. `scripts/build-marker-schema.mts` turns those inputs into the generated TypeScript catalog `marker-schema.ts`, which the compiler emits as the runtime `marker-schema.js`; contributors must not edit the generated file directly.

**Key generated exports:** `MARKER_SCHEMA`, `BUILTIN_MARKER_IDENTITIES`, `BUILTIN_MARKER_DOT_KEY_ALIASES`, `getBuiltinMarkerId()`, `getBuiltinMarkerDotKey()`, `resolveBuiltinMarkerDotKey()`, `CUSTOM_MARKER_ID_PREFIX`, and `isCustomMarkerId()`.

See [Marker model and category placement](/developers/marker-model) for the authoring and migration contract.

---

### `unit-profiles.ts` and `secondary-unit-conversions.ts`

Schema-wide display-unit projection over canonical marker storage. `unit-profiles.ts` resolves every built-in marker for `EU` (International/SI), `ANZ` (Australia/New Zealand), and `US`; markers without a numeric difference use an identity projection. `secondary-unit-conversions.ts` supplies compatible input and alternate clinical units. Import, manual entry, active data, ranges, reports, and AI context must use these central contracts rather than renderer-specific conversions.

**Key exports:** `UNIT_PROFILE_IDS`, `UNIT_PROFILE_LABELS`, `ANZ_UNIT_OVERRIDES`, `normalizeUnitProfile()`, `getUnitProfileLabel()`, `resolveMarkerUnitProfile()`, `convertCanonicalToDisplay()`, `convertDisplayToCanonical()`, `getMarkerInputUnits()`, `convertUnitInputToCanonical()`, `convertCanonicalToInputUnit()`, and `auditUnitProfileCoverage()`.

---

### `custom-marker-identity.ts`

Creates and migrates category-independent `custom:*` IDs while preserving existing custom-marker dot keys. Legacy IDs are deterministic and migration is idempotent so offline devices converge.

**Key exports:** `createCustomMarkerId()`, `deriveLegacyCustomMarkerId()`, `ensureCustomMarkerIdentity()`, `migrateCustomMarkerIdentities()`, `getCustomMarkerId()`, `getCustomMarkerDotKey()`, and `resolveCustomMarkerDotKey()`.

### `marker-placement.ts`

Pure marker placement engine and storage/display boundary. It validates visual category assignments, keeps unknown metadata forward-compatible, applies placement as the final active-data projection, and resolves mutation keys back to immutable storage locations.

**Key exports:** `migrateMarkerPlacements()`, `resolveMarkerIdentity()`, `getMarkerPlacementPlan()`, `setMarkerPlacement()`, `clearMarkerPlacement()`, `applyMarkerPlacements()`, `getMarkerStorageDotKey()`, and active-marker lookup helpers.

### `marker-terminology.ts`

Generated, optional mapping registry for LOINC, NPU, NČLP, and UCUM metadata. It is not part of application startup, profile persistence, import/export, backup, sharing, or sync.

**Key exports:** `TERMINOLOGY_CATALOGS`, `MARKER_TERMINOLOGY_REGISTRY`, `getMarkerTerminologyMappings()`, and `findMarkerTerminologyMapping()`.

### `adapters.ts`

Startup-safe parser adapter registry for specialty lab detection and normalization. It owns the shared specialty definitions; importer-only product catalogs such as Mosaic OAT/MOAT stay outside the startup graph.

**Key exports:**
- `ADAPTER_MARKERS` — flat object keyed by `"category.markerKey"`: `{ name, unit, refMin, refMax, categoryLabel, icon, group, singlePoint? }` (225 entries). Re-exported from `schema.ts` as `SPECIALTY_MARKER_DEFS`
- `getAllAdapterMarkers()` — returns merged marker map from all registered adapters
- `detectProduct(fileName, pdfText)` — runs all adapter `detect()` functions, returns `{ adapter, product: { prefix, label } }` or `null`
- `normalizeWithAdapter(adapter, markers, fileName, pdfText, product)` — dispatches to `adapter.normalize()` for post-AI marker key/category rewriting
- `getAdapterByTestType(testType)` — looks up adapter by AI-returned test type string

**Adapter registry:** array of `{ id, testTypes[], markers, productScoped?, detect?, normalize? }`:
- `fattyAcids` — 34 markers, detects Spadia/ZinZino/OmegaQuant by filename/text, normalizes to product-prefixed categories under the **Fatty Acids** sidebar group
- `metabolomix` — no unique startup markers; detects Genova Metabolomix+ and delegates importer-only normalization to stable `metabolomix*` categories
- `mosaicOat` — no startup markers; detects Mosaic/Great Plains OAT and MOAT reports, then uses the lazy 77-definition OAT or 21-definition MOAT catalog
- `oat` — 165 legacy/shared definitions; new imports are normalized to a laboratory-scoped marker space while existing legacy profiles remain readable
- `gutStool` — 3 shared stool/gut-barrier markers
- `biostarks` — 23 markers, detects BioStarks dried blood spot reports by filename/text, normalizes specialty markers (amino acids, serum FA, intracellular minerals, hormones, vitamins) while passing standard blood markers through to schema categories (hybrid import)

`mosaic-oat-catalog.ts` defines the importer-only Mosaic analyte order, aliases, sections, units, and OAT/MOAT marker metadata. `pdf-import-organic-acid-normalization.ts` maps AI output into Mosaic, Metabolomix+, or lab-scoped OAT keys. Keep product identity in this deterministic post-AI layer; do not rely on model-generated category names to separate histories.

**Window exports:** none

### `hardware.ts`

GPU detection and model fitness advisor for Local AI settings. Pure functions, no DOM manipulation.

**Key exports:**
- `detectHardware()` — async, returns `{ gpu: { name, vram, unified, renderer, source }, ram: { gb, source }, cpuThreads }`. GPU detected via WebGL `WEBGL_debug_renderer_info` matched against 75-entry `GPU_DB` (Apple Silicon M1–M4, NVIDIA RTX 30/40/50, AMD RX 6000/7000, Intel Arc, Vega)
- `assessModel(modelObj, hardware)` — returns `{ tier, badge, vramNeeded, label }` where tier is `'fits'` / `'tight'` / `'toobig'` / `'unknown'`
- `assessFitness(modelName)` — rates a model for getbased lab analysis: `{ tier, note }` where tier is `'recommended'` / `'capable'` / `'underpowered'` / `'inadequate'`. Benchmarked against Sonnet 4.6
- `getBestModel(modelDetails, hardware)` — picks the highest-fitness installed model that fits in VRAM
- `getUpgradeSuggestion(modelDetails, hardware)` — returns a pull recommendation if no installed model is "recommended" tier
- `saveHardwareOverride(vram)` / `getHardwareOverride()` — manual VRAM override in localStorage

**Window exports:** none (imported by `settings.ts`)

### `api-transport.ts`

Shared AI API transport helpers used by `api.ts`.

**Key exports:**
- `fetchWithRetry(url, options, config)` — wraps fetch with request timeout, transient network retry, and 429 backoff
- `createProxyFetch(shouldUseProxy)` — compatibility fetch selector used by the shared OpenAI-format helper. Current Custom API calls pass `false`, so Custom validation, model discovery, and chat are browser-direct and do not fall back to a relay.

### `app-extension-runtime.ts` and `app-extension-bootstrap.ts`

Neutral single-extension boundary for trusted edition builds. The public/self-host bootstrap installs no extension, leaving the independently runnable core behavior unchanged. This is a build-time adapter contract, not dynamic plugin loading.

**Hook groups:** Settings slots/actions/lifecycle, onboarding slots/actions, AI ownership/authorization/transport/model policy/options/error mapping, voice request authorization/playback policy, sync keys/encrypted prefixes/conflict policy/post-apply callback, and startup.

An extension requires a stable ID. Active extension-owned AI transport fails closed when `authorizeRequest` is absent or does not return `true`.

### `unique-id.ts`

Creates collision-resistant local record IDs with `crypto.randomUUID()` or `crypto.getRandomValues()`. `createUniqueId(prefix?)` throws when Web Crypto is unavailable instead of persisting a weak fallback identifier.
- `readWithStallTimeout(reader, label, timeoutMs?)` — guards one streaming read; Local AI uses the extended allowance only before its first token
- `STREAM_STALL_TIMEOUT_MS`, `LOCAL_AI_FIRST_TOKEN_STALL_MS`, `FETCH_REQUEST_TIMEOUT_MS`, `AI_IMPORT_REQUEST_TIMEOUT_MS` — transport timeout constants

**Window exports:** none

### Voice subsystem

Voice is a first-use chat subsystem rather than part of the startup bundle. `voice-loader.ts` keeps microphone capture and speech dependencies cold until the user records, listens, or enables automatic reading. It binds each pending action to the active chat thread and message so late transcription or speech work cannot update a stale conversation.

**Chat orchestration:**

- `voice-controller.ts` owns microphone state, transcript insertion, per-message playback, automatic reading, cancellation, and thread/message identity checks.
- `voice-capture.ts`, `voice-player.ts`, `voice-audio.ts`, and `voice-text.ts` own ephemeral recording, progressive audio playback, PCM/WAV handling, and safe speech-text normalization/chunking.
- `voice-service.ts` and `voice-provider-registry.ts` select the configured STT/TTS provider without coupling chat controls to provider implementations.

**Provider paths:**

- `voice-provider-browser-local.ts` runs downloaded Whisper STT and Kokoro TTS through `voice-local-stt-worker.ts`, `voice-local-tts-worker.ts`, and the serialized `voice-local-engine.ts` worker controller.
- `voice-provider-local-server.ts` calls OpenAI-compatible `/v1/audio/transcriptions`, `/v1/audio/speech`, and `/v1/models` endpoints directly from the browser.
- `voice-provider-ai-cloud.ts` supplies the xAI adapter plus the OpenRouter, PPQ, and Venice audio paths; `voice-provider-elevenlabs.ts` supplies ElevenLabs. Both use `voice-provider-cloud-shared.ts` for browser-direct calls after cloud-processing consent.
- `voice-provider-catalog.ts` owns capability and execution-location metadata; `voice-model-catalog.ts` pins local models, voices, languages, download sizes, and CPU/WebGPU modes.

**Settings and storage:**

- `settings-voice-panel.ts`, `settings-voice-view.ts`, `settings-voice-model-controller.ts`, and `settings-voice-hardware.ts` own the **Settings → Voice** UI, downloads, connection tests, voice catalogs, and hardware guidance.
- `voice-settings-schema.ts` is the authority for device-local, syncable, secret, and backup keys. `voice-settings-storage.ts` validates preferences and delegates secret writes to encrypted provider storage.
- Downloaded model assets and fetched voice catalogs are rebuildable caches. They are not sync payloads or backup data.

**Network boundary:** cloud voice is direct browser transport. Do not document or restore the removed `/api/voice` relay without a new reviewed privacy and consent design.

**Key exports:** `loadVoiceModule`, `toggleVoiceRecording`, `toggleMessageSpeech`, `maybeAutoReadAssistantMessage`, `stopVoiceActivity`, `getVoiceSettings`, `setVoiceSetting`, `transcribeVoice`, `createVoiceSynthesizer`

**Window exports:** none; chat and shell actions use module callbacks.

### Wearables vendor adapters

Each connected source ships as a pair: `wearables-<vendor>.js` (read API) + `wearables-<vendor>-auth.js` (OAuth dance). Apple Health and Manual skip the auth half. Tokens are always encrypted in the per-profile device-local vault and are excluded from sync and backups. They do leave the browser transiently when the selected OAuth exchange, refresh, or provider call requires the operated or self-hosted compatibility endpoint.

**OAuth2 confidential clients:** Oura, Withings, Polar, Google Health, and WHOOP inject the deployment secret at the compatibility endpoint. Google Health and WHOOP additionally require explicit server capability gates; Google Health credentials and raw rows use the always-on device-local key.

**Other OAuth paths:** Ultrahuman follows its reviewed experimental self-host contract. Fitbit's PKCE modules remain only for already-connected legacy users; the adapter is hidden for new connections and has no reconnect flow.

**No OAuth:** `wearables-apple-health.ts` (file-import — `parseAppleHealthXml` reads the `export.xml` from a Health zip), `wearables-manual.ts` (`logManualMetric` / `logManualBP` + `MANUAL_TAGS` whitelist for what users can log by hand).

**L1 storage + summary derivation:** `wearables-store.ts` (per-profile IndexedDB at `labcharts-wearables-{profileId}`; two-phase upsertDailyBatch), `wearables-summary.ts` (L2 derivation; vendor sources read a 90-day window, while sparse manual rows read all history so older hand-entered BP/pulse/weight entries stay visible; write gate — 5% d7 shift / trend flip / 14d force-refresh / source flip / metric removal triggers).

**UI surface:** `wearables.ts` (dashboard strip, source picker, reorder mode, empty-card manual-log forms, and legacy window facade), `wearables-detail-modal.ts` (metric detail modal, Chart.js series, manual-entry list/add/delete, focus trap, EMF sleep nudge), `wearables-formatters.ts` (shared value/date formatting), `wearables-manual-form-ui.ts` (shared manual chip/note form snippets), `wearables-settings-panel.ts` (Settings → Wearables rows, connect/sync/backfill/disconnect actions, Apple Health file-import UI, manual-source counts/delete action, strip visibility toggle), `brand-assets.ts` (per-vendor logo registry — `iconLight/Dark` for in-app rows, `signInLight/Dark` for landing-site Connect buttons, `mono` SVG fallback while a vendor logo is gated).

### Knowledge Base in-browser stack

`lens.ts` is the dispatcher; the 4 sibling `lens-local-*` modules are the in-browser implementation. The dispatcher routes between in-browser and external-server backends per the user's selection.

- `lens-local.ts` — main-thread shell: spawns a module worker, posts ingest/query/list/activate/delete messages, exposes a Promise-based API to `lens.ts`.
- `lens-local-worker.ts` — module worker. Loads transformers.js (currently from jsdelivr — see `update-vendor.sh` notes), runs WebGPU embedding when available with WASM fallback, owns OPFS persistence (`FileSystemSyncAccessHandle`), library CRUD, MMR re-rank (λ named `MMR_LAMBDA`), per-library model selection from a 4-model catalog.
- `lens-local-utils.ts` — pure helpers: `chunkText`, `mmrSelect`, hashing, vector-pack helpers. Importable from both threads.
- `lens-local-parsers.ts` — main-thread document parsers (PDF via `pdfjs-loader.ts`, DOCX via mammoth, ZIP via JSZip, plus plain text/markdown/CSV).
