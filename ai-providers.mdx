getbased supports several AI provider paths for PDF import, chat, and dashboard AI features: OpenRouter, PPQ, Routstr, Venice, Custom API, and Local AI. Some providers also expose private or encrypted modes, such as PPQ Private TEE and Venice Encrypted TEE Mode. You can switch between providers at any time in **Settings → AI** without losing any data. API keys are stored in your browser profile. Built-in provider and Local AI keys go directly to their endpoints; Custom API requests may pass through getbased's same-origin proxy, which forwards keys without storing them.

<Note>
Voice uses a separate service chosen in **Settings → Voice**. You can keep dictation and spoken replies on-device, connect a compatible voice server, or use xAI or ElevenLabs without changing the AI provider that generates chat answers. See [Use voice in AI chat](/guides/voice).
</Note>

## Which features need AI?

| Feature | Requires AI? |
|---|---|
| PDF import | Yes |
| AI chat panel | Yes |
| Focus card (dashboard insight) | Yes |
| Live context-card summaries and status dots | Yes (demo profiles include precomputed versions) |
| Live AI-generated card tips | Yes (demo profiles include precomputed versions) |
| Web search in chat | Yes (OpenRouter, PPQ, Venice) |
| Test AI models with the built-in report | Yes |
| Charts, tables, trend alerts | No |
| Manual entry | No |
| JSON export / import | No |
| Correlations, compare dates | No |

All non-AI features work fully without any provider configured. You can load a demo profile, enter results manually, and explore charts and trends before setting up AI.

<Tip>
The built-in demo profiles ship with precomputed context-card insights. Local AI can recalculate edited demo cards automatically, while cloud and other potentially paid providers stay off for demo-card recalculation until you explicitly enable live AI for the selected provider and model. The consent is session-only, so a reload or model/provider change requires a new confirmation. See [Health context](/guides/context-cards#demo-profiles-and-ai-cost).
</Tip>

## Set up a provider

<Tabs>
  <Tab title="OpenRouter">
    OpenRouter is the easiest way to get started. It gives you access to 200+ models — Claude, GPT, Gemini, DeepSeek, Grok, Qwen, and more — with a single account. Pay with a card or USDC. Supports web search in chat.

    **Connect with OAuth (easiest):**

    <Steps>
      <Step title="Select OpenRouter in Settings">
        Open **Settings** (gear icon in the header) and go to the **AI** tab. Select **OpenRouter**.
      </Step>
      <Step title="Click Connect with OpenRouter">
        Click the **Connect with OpenRouter** button. You'll be redirected to OpenRouter to authorize getbased. No API key needed — the app handles the token exchange automatically.
      </Step>
      <Step title="Choose a model">
        Back in Settings, pick a model from the curated dropdown. Recommended models are sorted first and marked with a star.
      </Step>
    </Steps>

    **Connect with an API key:**

    <Steps>
      <Step title="Get an API key">
        Create an account and generate an API key at [openrouter.ai](https://openrouter.ai).
      </Step>
      <Step title="Paste your key in Settings">
        Open **Settings → AI**, select **OpenRouter**, and paste your API key.
      </Step>
      <Step title="Choose a model">
        Pick a model from the dropdown, or type any OpenRouter model ID into the custom input field.
      </Step>
    </Steps>

    <Tip>
      The OAuth connect button also appears in the chat panel when no provider is configured — you can set up OpenRouter without going to Settings.
    </Tip>
  </Tab>

  <Tab title="PPQ">
    PPQ is a pay-per-query AI aggregator with 300+ models. No subscription, no KYC, no identity verification. Top up directly in the app with Bitcoin, Lightning, Monero, Litecoin, or Bitrefill gift cards. Supports web search in chat.

    <Steps>
      <Step title="Select PPQ in Settings">
        Open **Settings → AI** and select **PPQ**.
      </Step>
      <Step title="Create an account">
        Click **Create Account**. This is instant and requires no signup form — PPQ accounts are fully anonymous.
      </Step>
      <Step title="Save your API key">
        Copy your API key and store it somewhere safe. PPQ accounts are anonymous with no recovery mechanism — if you lose the key, you lose access to your balance.
      </Step>
      <Step title="Top up your balance">
        Click **Top Up** and follow the payment flow. The app shows a QR code and polls for payment confirmation. Supported: Lightning, Bitcoin, Monero, Litecoin, Aqua, and Bitrefill gift cards.
      </Step>
      <Step title="Choose a model">
        Pick a model from the curated dropdown. Your balance is displayed with color coding so you always know what you have available.
      </Step>
    </Steps>

    You can also paste an existing API key from [ppq.ai](https://ppq.ai) if you already have an account.

    <Tip>
      **Private TEE mode:** When PPQ advertises supported private models, enable **Private TEE mode** to encrypt prompts and responses between your browser and a verified Tinfoil enclave. No local proxy is required. The green **🔒✓** indicator appears after attestation succeeds. Web search is disabled while Private TEE mode is active.
    </Tip>
  </Tab>

  <Tab title="Routstr">
    Routstr is a decentralized AI network powered by Bitcoin micropayments. getbased has a built-in Cashu eCash wallet — fund it with Lightning, then connect to any Routstr node discovered via Nostr relays. Your prompts go directly from your browser to the node you choose. No account, no subscription.

    <Steps>
      <Step title="Select Routstr in Settings">
        Open **Settings → AI** and select **Routstr**.
      </Step>
      <Step title="Fund your wallet">
        Click **Deposit** and pay the Lightning QR code (or paste a Cashu token from an external wallet). Your wallet balance is shown in the settings panel.
      </Step>
      <Step title="Pick a node">
        The app discovers online Routstr nodes via Nostr relays. Click **Connect** on any node in the list.
      </Step>
      <Step title="Deposit sats to the node">
        Choose how many sats to deposit to the node for your session. You receive a session key that authenticates your requests.
      </Step>
      <Step title="Start chatting">
        Your wallet balance and your node session balance are shown separately. You can move sats between them freely at any time.
      </Step>
    </Steps>

    **Wallet features:**

    - **Seed phrase** — a 12-word BIP-39 mnemonic is generated on your first deposit. Write it down — it is the only way to recover your wallet on another device.
    - **Lightning withdraw** — send sats to a Lightning address or pay a BOLT11 invoice.
    - **Cashu token send/receive** — withdraw as a shareable Cashu token, or deposit one from an external wallet.
    - **Node withdraw** — pull remaining sats back from a node into your local wallet.

    <Warning>
      Your seed phrase is shown once when you first deposit. You can view it again from the wallet menu under Seed & Restore. Without it, your wallet cannot be recovered.
    </Warning>

    For the full wallet, refund, token export, and recovery behavior, see [Routstr AI provider](/guides/routstr).

    <Tip>
      **Private TEE mode:** Nodes that support attested private models show a **Private TEE** badge. Enable the toggle to encrypt prompt and response bodies in your browser before the node forwards them to a verified Tinfoil enclave. The node can still see your session credential, selected model, request timing and size, network metadata, and billing information. Web search and image attachments are disabled.
    </Tip>
  </Tab>

  <Tab title="Venice AI">
    Venice is a hosted AI provider that advertises a no-log policy. That is a provider policy, not something getbased independently verifies. Venice also proxies access to third-party models. Web search is available with standard Venice models but disabled in encrypted mode.

    <Steps>
      <Step title="Get an API key">
        Create an account and generate an API key at [venice.ai](https://venice.ai).
      </Step>
      <Step title="Select Venice in Settings">
        Open **Settings → AI** and select **Venice**.
      </Step>
      <Step title="Paste your API key">
        Enter your API key in the field provided.
      </Step>
      <Step title="Choose a model">
        Pick a model from the dropdown. The model catalog identifies which current models support Venice's encrypted protocol.
      </Step>
    </Steps>

    <Tip>
      **Encrypted TEE Mode:** Message content is encrypted in your browser with ECDH, HKDF-SHA256, and AES-256-GCM. Before connecting, getbased requires full Intel TDX verification with DCAP and signed NVIDIA GPU evidence through NRAS. If either check fails, the encrypted session does not start. The **🔒 TEE + GPU** badge means both required checks passed; hover, focus, or tap it for the individual results and remaining limits. The checks do not prove that the TDX environment and GPU run together, enforce an approved Venice code-measurement allowlist, or independently verify the source of every response. The API key, model, roles, request settings, timing, sizes, and network metadata remain visible to Venice. Web search and image attachments are disabled.
    </Tip>
  </Tab>

  <Tab title="Custom API">
    Connect any OpenAI-compatible API endpoint with your own base URL and API key. Works with OpenAI, Mistral, Groq, Together, xAI, Fireworks, Deepinfra, vLLM, LiteLLM, and any service that implements the `/v1/chat/completions` standard.

    <Steps>
      <Step title="Select Custom in Settings">
        Open **Settings → AI** and select **Custom**.
      </Step>
      <Step title="Enter your base URL">
        Type the base URL of your endpoint — for example, `https://api.openai.com/v1`.
      </Step>
      <Step title="Enter your API key">
        Paste your API key for the service.
      </Step>
      <Step title="Validate and pick a model">
        Click **Save & Validate**. The app checks your key and fetches the model list from your endpoint. Pick a model from the dropdown, or type a model ID manually if your endpoint doesn't expose a `/v1/models` listing.
      </Step>
    </Steps>

    <Tip>
      Use Custom when you have a direct API key for a service that is not one of the built-in providers. If the service is available through OpenRouter or PPQ, those are easier — they handle model discovery and show pricing automatically.
    </Tip>

    <Note>
      Public Custom API endpoints may be called through getbased's same-origin proxy when direct browser CORS is unavailable. The proxy validates the destination and forwards the request and API key without storing them. Local and private-network Custom URLs are called directly.
    </Note>
  </Tab>

  <Tab title="Local AI">
    Connect directly to an OpenAI-compatible server. That server can run on this device, another machine on your LAN, or a remote host. getbased identifies the execution location in Settings so you can distinguish truly local models from LAN, remote, and cloud-hosted models.

    <Warning>
      **Local AI describes the connection type, not a privacy guarantee.** Only a loopback server such as `localhost`, `127.0.0.1`, or `[::1]` running a downloaded model keeps requests on this device. LAN and remote endpoints send data off this browser device, and Ollama `:cloud` models run on Ollama's servers.
    </Warning>

    <Steps>
      <Step title="Choose a compatible server">
        Install a server locally or obtain the address of a compatible endpoint:

        - [Ollama](https://ollama.com) — command-line, easiest setup
        - [LM Studio](https://lmstudio.ai) — GUI with drag-and-drop model loading
        - [Jan](https://jan.ai) — open-source desktop app
        - llama.cpp, LocalAI, or any OpenAI-compatible server
      </Step>
      <Step title="Load a model">
        Download a model to run locally. In Ollama, for example:

        ```bash
        ollama pull qwen2.5:14b
        ```

        For reliable lab PDF parsing, use a model with at least 14B parameters. The built-in Model Advisor in Settings shows which of your installed models are suitable for lab analysis.
      </Step>
      <Step title="Select Local in Settings">
        Open **Settings → AI** and select **Local**.
      </Step>
      <Step title="Enter your server URL">
        The default is `http://localhost:11434` for Ollama. Enter the base URL for another local, LAN, or remote server. Add an API key if that endpoint requires one.
      </Step>
      <Step title="Test the connection">
        Click **Test**. getbased detects native Ollama and LM Studio servers when possible, otherwise it uses the standard OpenAI-compatible model list. Choose a text-generation model from the discovered list.
      </Step>
    </Steps>

    ### Native server support

    Ollama and LM Studio expose extra information beyond the compatible API. When detected, getbased can show loaded state, context length, quantization, model size, and VRAM use. It can also request a larger context for complex imports and release a loaded model when switching between supported servers on the same machine.

    On a current LM Studio server, a large import can reload the selected model at the planned context, verify the context LM Studio actually fitted into memory, and generate through the streaming compatible endpoint. If the previous instance cannot be unloaded, getbased checks whether it is really gone and otherwise stops with manual-unload guidance instead of loading a duplicate model into memory.

    Generic compatible servers continue to work through `/v1/models` and `/v1/chat/completions`, but they may not expose loaded state, context controls, native performance metrics, or model unloading.

    <Note>
      If getbased says the loaded context is too small, reload the model with a larger context or use a smaller or chunked input. Imports can request a larger native context from supported Ollama and LM Studio servers. getbased also rejects marker output cut off by the output or context limit instead of accepting a partial report.
    </Note>

    ### CORS setup

    The server must allow requests from the exact origin where you opened getbased. For the hosted app, that origin is `https://app.getbased.health`. Avoid `*` when the server supports an explicit origin, especially if API authentication is enabled.

    | Server | How to enable CORS |
    |---|---|
    | Ollama (Linux) | `OLLAMA_ORIGINS=https://app.getbased.health ollama serve` |
    | Ollama (macOS) | `launchctl setenv OLLAMA_ORIGINS "https://app.getbased.health"` then restart Ollama |
    | Ollama (Windows) | Add `OLLAMA_ORIGINS` = `https://app.getbased.health` as a system environment variable, then restart Ollama |
    | LM Studio | Enable CORS and API authentication in LM Studio Settings |
    | Jan | Settings → Advanced → Enable CORS |

    If you self-host getbased at another origin, replace `https://app.getbased.health` with the origin shown in your browser, including its scheme and port.

    <Warning>
      An HTTPS page cannot call a plain HTTP LAN or remote server because browsers block mixed content. Use an HTTPS endpoint, a loopback address, or an encrypted local tunnel. A self-hosted getbased page served over plain HTTP can call an HTTP LAN server when CORS permits it, but that traffic is unencrypted unless a VPN or tunnel protects it.
    </Warning>

    <Tip>
      The Model Advisor appears for discovered Local AI endpoints. It rates suitable text models for lab analysis and shows the metadata the server exposes. Ollama can also suggest a model to pull; remote servers let you enter their available VRAM for a fit estimate.
    </Tip>
  </Tab>
</Tabs>

## Recommended models

All providers show a tiered model dropdown with two groups:

- **Recommended** — the latest, most capable models for lab interpretation, sorted first
- **Other** — all remaining available models

Recommended models are chosen for accuracy with medical and scientific data. You can use any model, but recommended ones produce the most reliable results.

<Warning>
  **Use the same model for all your imports.** When you import a lab PDF, the AI generates marker keys (like `biochemistry.glucose`) to map results. Different models may generate slightly different keys for the same marker, which can cause the same biomarker to appear as two separate entries in your charts. Pick a model and stick with it. If you do switch, getbased runs a pre-flight check before each import and warns you if your model has changed since the last import.
</Warning>

## Test before you choose

Open **Settings → Data → Test models on lab reports** to run the same verified 68-result report through different setups. You can compare raw accuracy, getbased's corrected result, speed, tokens, and runtime details side by side.

The comparison works across local models, hosted compatible endpoints, and built-in cloud providers. You can also import the same personal report with different setups and compare the review effort each one required. See [Test and compare AI models](/guides/ai-model-testing).

## How much does it cost?

AI providers charge based on how much text is sent and received. getbased displays the exact cost of every interaction in the chat panel. Here is what real usage costs with the recommended models:

| Model | Provider | Import a lab PDF | Chat message | First month\* | Ongoing month\*\* |
|---|---|---|---|---|---|
| Claude Sonnet 4.6 | OpenRouter / Routstr / PPQ | ~$0.04 | ~$0.02 | ~$1.00 | ~$0.50 |
| GPT 5.4 | OpenRouter / Venice / Routstr / PPQ | ~$0.03 | ~$0.02 | ~$0.80 | ~$0.45 |
| Gemini 3.1 Pro | OpenRouter / Venice / Routstr / PPQ | ~$0.03 | ~$0.01 | ~$0.60 | ~$0.35 |
| Grok 4 | OpenRouter / Venice / Routstr / PPQ | ~$0.01 | ~$0.005 | ~$0.25 | ~$0.15 |
| Any model | Custom API (direct key) | Varies | Varies | Varies | Varies |
| Self-hosted model | Local AI (Ollama, LM Studio, Jan) | No provider fee | No provider fee | Electricity only | Electricity only |
| Hosted compatible model | Local AI / Custom API | Varies | Varies | Varies | Varies |

\* _First month: importing your first labs and setting up your profile through chat — typically 3–5 imports and 30+ chat messages._

\*\* _Ongoing month: 2–3 lab imports, 20–30 chat messages, dashboard AI features. Heavy users who chat daily may spend 2–3× more._

<Tip>
  Most users spend well under $1 per month. Every AI response in getbased shows its cost below the message, so you always know exactly what you are spending. If your credits run out, the app shows a clear message with a link to add more.
</Tip>

<Tip>
  Run a downloaded model on your own hardware with [Ollama](https://ollama.com), [LM Studio](https://lmstudio.ai), or [Jan](https://jan.ai) and pay no provider fee. You will need 8GB or more of VRAM — or a Mac with 16GB or more of unified memory — for capable models. The Model Advisor in Settings shows what fits your hardware.
</Tip>
