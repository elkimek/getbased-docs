# See what getbased asks AI

Whenever getbased uses AI, it sends an instruction that describes the job. Chat receives an instruction about answering health and lab questions. A report import receives a different instruction about extracting dates, markers, values, and ranges. Other features have their own focused instructions.

This guide lets you start with something you did in the app and answer four questions:

- What did getbased ask the AI to do?
- What information was included?
- Could I review or edit the message first?
- Where can I read the complete wording?

  Want to inspect the wording immediately? Go to [Find a prompt by feature](#find-a-prompt-by-feature), choose the action, and follow its link in the **Read** column.
</Info>

## A prompt in plain language

A request to an AI usually contains three parts:

~~~text
what getbased asks the AI to do
+ the information needed for that job
+ your question, file, image, or selected record
= the request sent to your chosen AI service
~~~

The first part is the **prompt** or **instruction**. It can set the AI's role, limits, writing style, and required answer format. The second part is the **context**—for example, enabled lab results or one Light & Sun session. The final part is the immediate task, such as your chat message or the report that needs to be read. Your **AI provider** is the outside service or local model you selected to process that request.

<Note>
  A prompt guides a model; it does not guarantee a correct answer. AI text can still be incomplete or wrong. Keep medical decisions with a qualified professional.
</Note>

## When you send a chat message

getbased sends the words you typed as your message. It does not silently rewrite them. Around that message, it can add the normal chat instruction, enabled profile information, recent conversation history, and optional tools such as a personality or Knowledge Base.

Here is the plain-language shape of a normal request:

~~~text
GETBASED'S INSTRUCTION
Act as the getbased lab analyst.
Use supplied facts and dates.
Explain patterns carefully and stay within the documented health boundaries.

INFORMATION ADDED FOR THIS CHAT
Enabled profile and lab context
Optional Knowledge Base passages
Optional personality
Up to the last 30 eligible conversation messages

YOUR MESSAGE
The exact text you sent
~~~

If you attach images, the current message also contains the prepared image data. If web search is enabled and supported, search results can be added before the answer is generated.

<Tip>
  Read the maintained [chat instruction](/developers/system-prompts-chat#prompt-chat-base) and the [optional chat additions](/developers/system-prompts-chat#prompt-chat-context). Braces such as `{enabled profile context}` stand for information filled in when you send.
</Tip>

### A simple example

Suppose you write: “Why has my ferritin fallen over the last year?”

The AI can receive:

- that exact question;
- the getbased chat instruction;
- enabled ferritin values, dates, ranges, and relevant notes;
- enabled supplement, medication, diet, cycle, or other profile context;
- recent messages in the same conversation;
- an optional personality and relevant Knowledge Base passages.

It does not automatically receive every stored item. The request uses the sources enabled for AI and the information selected for that feature.

## When you use Ask AI

An **Ask AI**, **Discuss**, or chat-shortcut button can create the user message for you. This app-written message is separate from the chat instruction, and both are documented.

Most feature buttons open chat with the message in the composer. You can read it, change it, or delete it before sending. A small number of explicit shortcuts send their documented message immediately after you click; the full list labels those actions.

For example, a marker action starts with a message shaped like:

~~~text
Tell me about my {marker name} results.
Values: {dated values and units}.
Current status: {status}.
What matters most, what does this mean, and should I be concerned?
Lead with the main takeaway and keep range comparisons brief.
~~~

The AI is asked to begin with one useful interpretation, not a list of every possible range. The range paired with the current status is its starting frame. If a supplied reference interval and optimal band lead to meaningfully different conclusions, it can summarize that difference in one sentence. It should bring in another published threshold only when you ask about alternatives or when the difference materially changes a safety-relevant interpretation.

An outside number is not treated as a special “model range.” With Web or a Knowledge Base source available, the AI is asked to identify the source and relevant population or purpose. Without a verifiable source, it should keep remembered thresholds secondary and make the uncertainty clear.

Other app-written messages cover correlations, Genome findings, recommendations, Biology Score coverage, supplement evidence, Light Audit comparisons, and EMF follow-up.

## Know what happens before sending

| Kind of action | What you can see first |
|---|---|
| Message you type | The exact message remains in the composer until you send it. |
| Most **Ask AI** actions | The app-written message appears in the composer and can be edited or removed. |
| Immediate chat shortcut | The documented message is sent after you deliberately click that shortcut. |
| Focused feature such as a summary or Light verdict | There is no chat composer. The feature uses its documented instruction and the selected record. |
| Report or product extraction | You select the file, image, or page first. Extracted facts appear in a review step before they are saved. |

<Warning>
  A review screen lets you correct AI-extracted results before saving; it does not mean the provider never received the selected file or prepared content. Check the feature's privacy note before starting an import.
</Warning>

## Control what information is included

For ordinary chat, open **Insight → Manage → Context** to choose which stored sources may influence later requests. Turning a source off keeps it stored but excludes it from new in-app AI context.

Depending on the action, a request can also include:

- recent messages from the current conversation;
- images attached to the current message;
- the report, product page, measurement, session, room, or assessment you selected;
- an active personality;
- selected Knowledge Base passages;
- web-search results when web search is enabled and supported.

The AI provider selected in **Settings → AI** receives the assembled request. A local or private connection can change where and how it is transported, but it does not remove information that the selected feature needs for the request.

See [Privacy and data storage](/guides/privacy), [Connect an AI provider](/ai-providers), and [Local encryption](/guides/encryption) for the storage and transport boundaries.

## Understand the wording you see

Read the full prompt blocks in two simple ways:

| Label | Meaning |
|---|---|
| **Exact wording** | The displayed sentences match the fixed wording maintained in the app. |
| **Template wording** | The fixed wording is shown, while changing values are replaced with braces such as `{report text}` or `{marker name}`. |

No public documentation can display a future request containing your live private information. Placeholders show where that information would appear without publishing it.

The prompt ID and source-file link on the full page are there for reviewers and contributors. You do not need to understand the code to read the instruction block.

## Understand the result

AI has different responsibilities in different features:

- **Chat and interpretations** return model-written explanations. They are not independently fact-checked.
- **Imports** return structured candidates that getbased parses, normalizes, and shows for review before saving.
- **Short dots and verdicts** accept only known display values and limit output length, but their wording is still AI-generated.
- **Biology Scores, calculated markers, displayed ranges and statuses, and Light dose calculations** come from fixed calculations or stored source data. AI can explain them and may compare them with clearly labeled external guidance, but it does not change what the app calculated or displayed.

If an import or verdict response is missing the fields getbased expects, it normally fails, falls back to a neutral state, or stays out of saved data. A valid-looking answer can still be factually wrong, so review important results.

## Common questions

<AccordionGroup>
  <Accordion title="Does getbased rewrite what I type in chat?">
    No. Your current text is sent as the user message. The app adds its instruction and permitted context around it. Image attachments change the technical message format, but not the text you wrote.
  </Accordion>
  <Accordion title="Does every chat send my entire profile?">
    No. Chat uses enabled context sources and limited summaries. Feature-specific actions can add the selected marker, finding, or record. Use **Insight → Manage → Context** to turn sources on or off.
  </Accordion>
  <Accordion title="Does Ask AI use a hidden extra prompt?">
    It uses the normal chat instruction plus an app-written user message for that action. Most of those messages are visible and editable in the composer. All current templates are listed under [app-written chat messages](/developers/system-prompts-chat#prompt-chat-prefills).
  </Accordion>
  <Accordion title="Which marker range does chat use?">
    Chat starts with the range paired with the status supplied by getbased. It is told to treat that range as a comparison frame rather than universal medical truth. Routine answers should not list every available range. When a lab interval, optimal band, or relevant published threshold changes the takeaway, chat should state the difference briefly and label which frame produced each conclusion. You can always ask for a deeper range or source comparison.
  </Accordion>
  <Accordion title="Can I change the main instruction?">
    The main extraction and analysis instructions are maintained with the app because changes can affect safety, parsing, and compatibility. You can change your message, enabled context, personality, Knowledge Base, web-search setting, provider, and model.
  </Accordion>
  <Accordion title="Does private or encrypted mode use a different health prompt?">
    The health instruction remains the same. The transport can add a short private-mode note and changes how the request reaches the provider. See [Privacy and data storage](/guides/privacy) for the exact boundary.
  </Accordion>
  <Accordion title="Do dictation and Listen add another prompt?">
    No developer health prompt is added for voice transcription or speech synthesis. Those services receive the recording or text-to-read together with their selected voice settings. They can use a different provider from chat.
  </Accordion>
</AccordionGroup>

## Report or propose a change

If an instruction looks unclear, biased, unsafe, too broad, or inconsistent with the feature:

<Steps>
  <Step title="Name the action">
    Say what you clicked or what feature ran, such as **Ask AI on a marker** or **Import report photos**.
  </Step>
  <Step title="Link the prompt">
    Use the relevant **Read** link above so reviewers can find the maintained wording quickly.
  </Step>
  <Step title="Describe the problem">
    Explain the behavior you saw, what you expected, and why the wording may have contributed.
  </Step>
  <Step title="Remove private information">
    Replace health values, names, report text, credentials, private Knowledge Base content, and other identifying information with made-up examples.
  </Step>
  <Step title="Open a public issue">
    Use the [GitHub issue tracker](https://github.com/elkimek/get-based/issues). Maintainers can follow the [technical prompt review workflow](/developers/system-prompts#review-workflow).
  </Step>
</Steps>

<Warning>
  Never paste an API key, share password, OAuth token, Cashu token, raw health report, or identifiable medical record into a public issue.
</Warning>
